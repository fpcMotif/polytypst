# polytypst

- **Books**: before you build a book edition (`polytypst build`), check one against its scan (`polytypst parity`), audit quality and native numbering (`polytypst audit`), fix a book's figures, tables, notes, headings or equations, or add a book (`books/<key>/book.toml`), read `docs/scanned-books.md`.
- **Numbering**: sections, paragraphs, equations, figure captions, cross-references, and citations use counters, labels, and `@ref`/`\ref`/`\hyperlink` via `src/compiler/source_numbers.py` (`cross_references=True`), checked by `src/literal_numbers.py`.
- **Review**: before you review any output folder against its scan, redshift its pages, record findings, or track a rebuild's measures (`polytypst review`, `polytypst checklist`), read `docs/reviewing-books.md`.
- **Look review**: before you hold every page of a book to the publisher bar (`docs/publisher-bar.md`) against its scan, brief page-group agents, or merge their findings, read `docs/prompts/look-review.md`. Run each step through `scripts/look_review.py` (`prepare`, `status`, `brief`, `check`, `merge`).
- **Page check**: before you check transcript pages against their scan, word by word and table cell by table cell (`polytypst page-check text|suspects|cells|tablediff`), read `docs/page-check.md`. Before you lint a transcript, start the checking agents, or verify, fix and record their issues (`polytypst page-check status|lint|run|triage|verify`), read `docs/page-check-review.md`.
- **Math books**: before you check, review or audit one or all rebuilt math books, or write a script to check one, read `docs/prompts/math-book-check.md`. It starts with `uv run python scripts/math_books.py`.
- **Double-check**: before you write a double-check prompt for a math or CS textbook, or hold a rebuild to a publication bar, read `docs/double-check-guide.md`.
- **Corrections**: every fix to a book's text or a defect cause (a `book.toml` rewrite, a hook, `src/compiler/`, a workflow step) gets one line in `quality/corrections.jsonl` when you make it: `date`, `book`, `page`, `kind` (`ocr`, `scan_typo`, `code`, `workflow`), `before`, `after`, `scan_reads`, `finding`, `evidence`, `fixed_in`, `commit`. A shared cause also gives `test` and `books_covered`.
- **Evidence**: before you blame code for a wrong word, note or call mark (①②), change shared code in `src/compiler/`, or attach scan proof to a finding (`polytypst evidence`), read `.claude/skills/scan-evidence/SKILL.md`.
- **OCR**: before you transcribe a scan (`polytypst SCAN.pdf --backend`) or add an OCR backend (`src/ocr/backend.py`), read "Transcribe the scan" in `docs/scanned-books.md`. To hand a fresh OCR run to an agent, fill in `docs/prompts/fresh-ocr.md`.
- **Design**: before you design or split a module in `src/` or `books/`, add a compiler pass, OCR backend or per-book hook, decide where a seam goes between the Python and the Typst or LaTeX it writes, or review the architecture, read `.claude/skills/deep-modules/SKILL.md`.
- **PDF**: use `import pymupdf` and `pymupdf.open(path)` in files, `eval`, and `python -c` (`fitz` is deprecated). Outside the repo, such as in the scratchpad, run them with `uv run --project <repo root> python ...` so uv loads the project's pymupdf.
- **LaTeX**: compile `.tex` files to PDF with `tectonic -X compile FILE.tex` (`~/.local/bin/tectonic`), which runs XeTeX and fetches packages on demand. TeX Live is not installed, so do not run `xelatex`, `tlmgr` or `latexmk`.
- **Terms**: `GLOSSARY.md` names the source scan, rebuilt PDF, page map, scan parity, transcript, transcript store, backend, page check, and verdict.
